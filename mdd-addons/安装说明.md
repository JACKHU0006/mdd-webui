# 补齐功能安装说明

这份文档把 `mdd-addons/` 里六个功能的安装步骤**集中在一处**，按顺序照着做就行。
每个模块自己的文件末尾也有一份 `INSTALL_NOTES`，但那份是给读代码的人看的；
这一份是给「要把它装起来的人」看的。

> **目标**：把这些功能并进你自己的 MDD fork。
> **原则**：**全部是新增文件 + 少量登记行**，不改上游既有逻辑，所以以后合并上游更新不会冲突。

---

## 0. 总览

| # | 功能 | 新增文件 | 需要改上游吗 | 测试 |
|---|---|---|---|---|
| 1 | 大疆模块驱动修复 | `tools/mdd-modem-driver-repair.py` | **不用** | 19 项 |
| 2 | AT / USSD 终端 | `control/app/at_terminal.py`<br>`control/app/at_terminal_api.py` | `main.py` 2 行 | 70 项 |
| 3 | Bark / 邮件通知渠道 | `control/app/notify_channels.py` | `notify_push.py` 3 处<br>`main.py` 2 处 | 59 项 |
| 4 | Telegram 双向 Bot | `control/app/telegram_bot.py` | `main.py` 1 段 | 52 项 |
| 5 | 多 eUICC 清单 | `control/app/esim_inventory.py`<br>`control/app/esim_inventory_api.py` | `main.py` 2 行 | 35 项 |
| — | 前端（十个页面） | 见 `../mdd-webui/` | 独立仓库，不用并 | 7 个脚本 |

**上游改动合计**：`main.py` 约 40 行、`notify_push.py` 约 10 行。都是新增，没有一行是改逻辑的。

## 3. 改 `control/app/main.py`

一共四处。都在文件顶部附近或路由注册区，找同类语句放旁边就行。

### 3.1 导入（放在其它 `from . import ...` 旁边）

```python
from . import at_terminal_api
from . import notify_channels
from . import esim_inventory_api
```

> `notify_channels` 是给第 3.4 步的校验和测试端点用的。

### 3.2 注册两个路由（放在其它 `app.include_router(...)` 或路由定义之后）

```python
app.include_router(at_terminal_api.router)
app.include_router(esim_inventory_api.router)
```

> 如果 `main.py` 里没有用过 `include_router`（它的路由都是 `@app.get(...)` 直接挂的），
> 那就放在文件里**任意一个** `@app.get` 定义之前或之后都行 —— FastAPI 对顺序不敏感。
> 只要在 `app = FastAPI(...)` 之后就可以。

### 3.3 设置校验（放在已有飞书校验的旁边）

在 `PUT /api/settings` 的处理函数里，找到校验飞书渠道的那几行，在附近加上：

```python
for key, validate in notify_channels.VALIDATORS.items():
    if key in patch:
        try:
            validate(patch[key] or {})
        except ValueError as exc:
            raise HTTPException(400, str(exc)) from None
```

### 3.4 两个测试端点（放在已有四个通知测试端点旁边）

```python
@app.post("/api/notifications/bark/test")
async def api_bark_test(body: dict):
    return await asyncio.to_thread(
        notify_channels.send_bark, body,
        _test_push_payload(_notification_test_event(body)))


@app.post("/api/notifications/email/test")
async def api_email_test(body: dict):
    return await asyncio.to_thread(
        notify_channels.send_email, body,
        _test_push_payload(_notification_test_event(body)))
```

> **注意发件函数在 `notify_channels` 里，不在 `notify_push` 里。**
> 这是最容易抄错的一处 —— 上游另外四个渠道的 senders 都在 `notify_push`，
> 照抄会把 `notify_channels` 写成 `notify_push`，然后在第一次点「发送测试」时才炸。

### 3.5 Telegram Bot 的启动

三小段。先加一组把网关能力包成回调的函数（放在 `main.py` 里靠近其它辅助函数的地方）：

```python
def _telegram_status() -> str:
    ...      # 复用概览页用到的那些计数
def _telegram_lines() -> str:
    ...
def _telegram_esim(line: str) -> str:
    ...
def _telegram_send_sms(line: str, to: str, text: str) -> str:
    ...
def _telegram_balance(line: str) -> str:
    ...
def _telegram_switch(line: str, iccid: str) -> str:
    ...
def _telegram_wfc(line: str, on: bool) -> str:
    ...
```

**实现要点：直接调用路由里已经在用的那些函数，不要绕 HTTP 请求自己。**
这样 bot 和控制台不可能给出不一致的答案。

然后是一个轮询循环：

```python
async def _telegram_loop(bot):
    offset = None
    while True:
        try:
            offset = await asyncio.to_thread(bot.poll_once, offset)
        except Exception as exc:  # noqa: BLE001
            log.warning("telegram poll failed: %s", type(exc).__name__)
            await asyncio.sleep(1)   # 网络断了不要空转
```

最后在 startup 钩子里启动：

```python
@app.on_event("startup")
async def _start_telegram():
    tg = (cfg.get_settings().get("telegram") or {})
    token = str(tg.get("bot_token") or "")
    allowed = tg.get("allowed_chat_ids") or []
    bot = telegram_bot.TelegramBot(
        token=token,
        allowed_chat_ids=allowed,
        actions=telegram_bot.GatewayActions(
            status=_telegram_status,
            lines=_telegram_lines,
            esim_profiles=_telegram_esim,
            send_sms=_telegram_send_sms,
            query_balance=_telegram_balance,
            switch_profile=_telegram_switch,
            set_wfc=_telegram_wfc,
        ),
        call=telegram_bot.http_call(token),
    )
    if bot.enabled:
        app.state.telegram_task = asyncio.create_task(_telegram_loop(bot))
    else:
        log.info("telegram bot disabled: 需要 bot_token 和 allowed_chat_ids")
```

> **`bot.enabled` 是「有 token **且** 有白名单」。**
> 白名单为空时 bot 不会启动 —— 这是刻意的。不要为了「先跑起来」把 `enabled` 改成只看 token，
> 那等于把网关的短信和 eSIM 交给任何找到这个 bot 的人。

## 4. 改 `control/app/notify_push.py`

三处。

### 4.1 顶部导入（和别的 import 放一起）

```python
from . import notify_channels
```

> 没有循环导入：`notify_channels` 只在函数内部（`_message()`）才回头引用 `notify_push`，
> 和 `mms_transport` 延迟导入 pyserial 是同一个做法。

### 4.2 `dispatch()` —— 在飞书循环之后、投递循环之前

```python
for key, sender in notify_channels.CHANNELS.items():
    extra = settings.get(key) or {}
    if extra.get("enabled") and _events_enabled(extra).get(event):
        deliveries.append((key, sender, extra))
```

### 4.3 `has_enabled_channel()` —— 把新键算进「有没有可用渠道」

```python
for key in ("webhook", "telegram", "pushplus", *notify_channels.SETTINGS_KEYS))
```

> 漏了这处不会报错，但「余额不足」这类依赖 `has_enabled_channel` 的检查会认为
> 没有任何渠道可用，于是**静默不发**。是个不响的坑。

## 6. 配置

### 6.1 Telegram 白名单

Bot 需要 `telegram.allowed_chat_ids`。**先拿到你自己的 chat id**：

1. 给 bot 发一条消息
2. 浏览器打开 `https://api.telegram.org/bot<TOKEN>/getUpdates`
3. 找 `result[].message.chat.id`

然后写进设置（`PUT /api/settings`，顶层浅合并，只提交 `telegram` 一个键是安全的）：

```bash
curl -sS --noproxy '*' -c /tmp/mdd.jar -X POST https://<你的域名>/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"username":"admin","password":"<密码>"}' -o /dev/null

CSRF=$(curl -sS --noproxy '*' -b /tmp/mdd.jar https://<你的域名>/api/auth/status \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["csrf"])')

curl -sS --noproxy '*' -b /tmp/mdd.jar -X PUT https://<你的域名>/api/settings \
  -H 'content-type: application/json' -H "x-mdd-csrf-token: $CSRF" \
  -d '{"telegram":{"enabled":true,"bot_token":"<TOKEN>","chat_id":"<你的id>","allowed_chat_ids":["<你的id>"]}}'
```

> `chat_id`（推送用）和 `allowed_chat_ids`（控制用）是两件事，前者可以只有你，后者也可以，
> 但**后者为空时 bot 不启动**。

### 6.2 AT 终端的只读开关

默认允许改状态的命令（查询和 USSD 永远允许）。如果这台机器只该被观察：

```bash
# 在控制面的环境里
MDD_AT_TERMINAL_ACTIONS=0
```

### 6.3 Bark 自建服务器

在通知页填「服务器」即可。**留空用公共的 `https://api.day.app`。**

> 自建服务器常常是明文 HTTP，那会把设备 Key 明文发出去。页面上写了这件事。

## 7. 回滚

因为改动都是新增的，回滚很干净：

```bash
cd my-gateway
git checkout main.py control/app/notify_push.py     # 只回滚两个改过的文件
rm control/app/at_terminal*.py control/app/notify_channels.py \
   control/app/telegram_bot.py control/app/esim_inventory*.py \
   tools/mdd-modem-driver-repair.py
```

或者如果你一开始就建了分支：`git checkout main`。

**注意**：回滚后设置文档里会留下 `bark` / `email` / `telegram.allowed_chat_ids` 这些键。
它们不会被读取，也不会报错 —— 上游的 `PUT /api/settings` 是顶层浅合并，多余的键只是被存着。
想清掉就再提交一次只含那几个键的 `PUT`（值设为 `null` 或空对象）。

## 8. 故障排查

| 现象 | 原因 |
|---|---|
| 启动报 `ImportError: cannot import name 'notify_channels'` | 文件没拷到 `control/app/` 下，或拷到了别的目录 |
| `/api/notifications/bark/test` 返回 500 | 3.4 抄成了 `notify_push.send_bark`（函数在 `notify_channels` 里） |
| 「发送测试」按钮点了没反应 | 3.3 的校验没加 —— 保存时被 400 拒了，但错误只显示在设置页顶部 |
| 通知页看不到两个新渠道 | 前端没更新。通知页的渠道列表在 `mdd-webui/src/views/Notifications.tsx`，那是**另一个仓库** |
| Telegram 发了命令没反应 | 1) `allowed_chat_ids` 为空或没含你的 id 2) 看日志有没有 `ignoring message from unauthorised chat` |
| Telegram 回「没有这个命令」 | 群聊里要 `@bot`，或者命令名拼错。`/help` 看列表 |
| AT 终端返回「只接受 AT 命令」 | 命令必须以 `AT` 开头。想查状态用 `AT+CSQ`、`AT+CREG?` 这类 |
| AT 终端一直「模块没有响应」 | ModemManager 不可用，或这条线路还没有 SIM 身份信息（ICCID/IMSI） |
| eUICC 清单是空的 | 点「读取所有卡」；如果还空，看面板里有没有列出读卡器 |
| eUICC 清单里的卡显示「未核实」 | 正常 —— 那张卡只在缓存里，没有任何读卡器报告它。点「读取所有卡」核实 |
