# 操作手册

本文面向**每天使用这个控制台的人**。假设网关已经装好并初始化完成（没装完请先看
[部署手册](部署手册.md)）。

左侧十一个入口，对应下面第 4–14 节。**第 3 节是五分钟快速上手**，赶时间可以先看那节。

---

## 1. 登录

打开控制台地址，输入管理员密码。密码要求 **10–256 字符**。

几个需要知道的行为：

- 会话默认有效 **12 小时**；勾选「记住我」是 **30 天**。
- 连续 **5 次**输错，当前来源会被锁 **60 秒**（不是锁账号，是锁这个 IP）。
  —— 所以如果反代没配好可信代理，几个人同时输错会互相锁住，见部署手册 5.2 的提示。
- 密码忘了需要到网关主机执行 `sudo ./install.sh reset-admin`。

**首次打开时**如果还没建管理员，界面会进创建流程 —— 注意在完成之前，任何能访问这个
端口的人都可以抢先申领管理员。

## 2. 界面速览

```
┌─ 侧栏 ────────┬─ 内容区 ────────────────────────────┐
│ ◈ 概览        │  页面标题 + 一句话说明               │
│ ▤ 设备        │                                     │
│ ≡ 线路        │                                     │
│ ☏ 通话        │                                     │
│ ⌘ AT 终端     │                                     │
│ ✉ 短信        │                                     │
│ ◷ 余额与保号  │                                     │
│ ▣ eSIM        │                                     │
│ ⇄ 网络出口    │                                     │
│ ◔ 通知        │                                     │
│ ⚙ 设置        │                                     │
├───────────────┤                                     │
│ 连接状态 实时 │                                     │
│ 语言 主题     │                                     │
└───────────────┴─────────────────────────────────────┘
```

> **这套系统有两个界面。** 网关本体自带一个 WebUI（`https://<网关主机>:8443`），
> 本控制台是通过 Worker/反代挂在你自己域名上的另一个前端。两者读同一份设置文档，
> **并存不冲突**。
>
> 日常操作用本控制台就够了。少数功能（更新策略、TLS 证书、Docker 清理、备份还原）
> **只在网关自带界面里**，本控制台没有渲染 —— 遇到时会明确指出来。

**左下角的「连接状态」是最重要的一行字**：

- **实时** —— WebSocket 通着，状态变化会立刻推过来。
- **重连中** —— 实时通道断了，界面靠 30 秒轮询兜底。

「重连中」不代表数据是错的，只代表不实时。页面顶部若出现「演示模式」提示条，
说明这是纯前端演示版，后面没有真网关。

## 3. 快速上手：从插卡到能打电话

| 步骤 | 去哪 | 做什么 |
|---|---|---|
| 1 | 设置 → 硬件 | 确认你的 USB 模块在列表里。大疆一代模块有一键加入按钮。 |
| 2 | 插卡 | 插上 SIM，等几秒 |
| 3 | 概览 | 应该出现这张卡；「设备」计数 +1 |
| 4 | 线路 | 找到新出现的卡，完成配置（MCC/MNC 通常能自动识别），启用 |
| 5 | 线路 | 等到状态变成 **RUNNING**（引擎日志里能看到 IKEv2 协商成功） |
| 6 | 短信 | 发一条给自己，确认通道通 |
| 7 | 通话 | 想用浏览器打电话 → 先配证书（见部署手册第 6 节）；只想用模块打 → 直接拨 |
| 8 | 余额与保号 | 配一条查询规则，让余额能被读到 |
| 9 | 通知 | 至少接一个渠道，否则出问题你不会知道 |

**第 1 步不能跳过。** 编排器拿 `(VID, PID)` 查表，查不到就当这块设备不存在 ——
插着也没用，而且表现和「设备没插」一模一样。

## 4. 概览

一眼看全局的页面。

| 指标 | 含义 |
|---|---|
| **设备** | 识别到的设备总数 |
| **在线线路** | 引擎跑起来的线路数 |
| **可用出口** | 就绪的国家出口数 |
| **最近短信** | 当前会话收到的推送条数（不是历史总数） |

下面是**主机告警**和**最近短信**两个列表。

- 主机告警来自宿主编排器（磁盘、Docker、USB 异常之类）。没有就显示「暂无主机告警」。
- 最近短信只保留最近若干条，完整的去「短信」页看。

**日常巡检看这里就够了**：三个计数是否正常 + 有没有主机告警。

## 5. 设备

设备页管的是**设备本身**，不是 SIM 线路（线路在下一页）。

### 三个能力互相独立

4G 数据、飞行模式、Wi-Fi Calling 是**三个独立状态**：

- 关掉 4G **不会**停掉 ModemManager，也**不会**隐式进入飞行模式。
- 每个开关是**单独发一次**请求的，一次只改一个。

**页面不会做乐观更新。** 你点下开关之后，界面会等控制面确认再变 —— 因为能力变更会重启
引擎的一部分，如果立刻把「期望值」画成「实际值」，你会以为隧道已经起来了，其实还在重启。

所以每个能力有三个东西：

| | 含义 |
|---|---|
| **期望** | 你设的值 |
| **实际** | 引擎现在真的在做什么 |
| **可用** | 这台硬件/这个运营商支不支持 |

**期望和实际不一致是正常的、也是有用的**：它说明变更还在进行，或者失败了（这时会有原因）。
如果「可用」是「不支持」，那就是运营商或硬件做不到 —— 比如某些运营商不提供 VoWiFi。

### 什么时候用飞行模式

网关**只在需要救回一条卡死的线路时**才强制飞行模式。日常不需要手动开。

## 6. 线路

**这是整个控制台的中枢。** 线路 = 一张 SIM + 一个隔离引擎容器。

### 一条线路的完整生命周期

1. **待配置（draft）** —— 插卡后自动出现，但还缺信息（通常是 MCC/MNC 或 IMEI）。
2. **配置** —— 补齐信息。绝大多数情况能自动识别，不用手填。
3. **启用** —— 引擎容器起来，开始 IKEv2 协商。
4. **RUNNING** —— 隧道建立，IMS 注册完成，能收短信、能打电话。
5. **STOPPED** —— 主动停掉。数据还在，随时能再启。

### 页面上的几块东西

**可用率时间线** —— 每个色块代表一段真实时长，不是等分的。中断 4 小时就画成比
中断 1 小时宽 4 倍，否则图表会说谎。

灰色的 **unknown** 段表示**控制面当时没在看**（比如控制面自己重启了）。
这一段**不计入可用率** —— 没观测到就是没观测到，不能算成「在线」也不能算成「离线」。

**引擎日志** —— IKEv2 协商、Asterisk、IMS 注册的原始日志。**排障第一个看这里。**

**国家出口** —— 这条线路走哪个国家的出口。留空则按 SIM 的 MCC 自动选。详见第 11 节。

### 编辑线路

可以改的：名称、ICCID、IMSI、MSISDN、MCC/MNC、IMEI/IMEISV、SMSC、P-CSCF、APN、
ePDG 身份编码方式、重协商周期。

两个值得注意的：

- **P-CSCF** —— 某些运营商的 IMS 要求显式指定。留空则从网络获取。
- **ePDG 身份编码（`idr_mode`）** —— 默认 `apn`（裸 APN）是验证过最稳的。
  个别运营商的 ePDG 要求用运营商 APN-FQDN，这时改成 `fqdn`。
- **重协商周期** —— 设为 0 表示不做主动重协商。

**PIN 码**只在需要重新进入时填。**留空永远不会清掉已存的 PIN** —— 这是故意的，
否则误保存一次就把卡锁死了。

## 7. 短信

### 收

左侧是**会话列表**（按对方号码分组），右侧是**该号码的完整历史**。

`GET /api/instances/{iid}/messages/{peer}` 返回的是**持久化的历史**，
不是内存里的推送缓冲 —— 所以翻旧短信是可靠的。

新短信通过 WebSocket 实时推过来，不需要刷新。

### 发

在输入框里写内容，回车或点发送。发送走的通道取决于这条线路当前的状态：

- 走 **IMS**（VoWiFi）—— 隧道通的时候
- 走 **模块**（蜂窝）—— 4G 数据可用的时候

页面上的传输方式选择器默认是 `auto`，会挑一条能用的。

### 模块存储策略（重要）

模块的短信存储空间很小，**写满之后就再也收不到短信了**。

新安装默认是「入库后从模块删除」。如果你在设置里改成了「保留」，记得偶尔清理，
否则迟早会静默地收不到短信。

## 8. 通话

**两条完全独立的通道**，页面分成两个面板：

| | 浏览器软电话 | 蜂窝通话 |
|---|---|---|
| 走哪 | IMS 隧道（VoWiFi） | 实体模块 + 运营商网络 |
| 需要什么 | 浏览器注册 + **有效证书** + 8089 端口可达 | 模块可用 |
| 没有浏览器时 | 不可用 | **照样能用** |

**它们互不影响。** 排查一条的时候不要被另一条的状态误导。

### 8.1 浏览器软电话

**连接是手动的** —— 点「连接软电话」才会去注册。页面打开时**不会**自己连，
因为注册要开一条 WSS 会话。

状态：

- **未注册** —— 没连，或者连了但还没注册成功
- **连接中…**
- **已注册** —— 可以拨号了
- **注册失败：<原因>**

**拨号按钮在未注册时是灰的。** 这不是 bug —— 控制面是通过 AMI 去「振铃浏览器端点」再桥接
到 IMS 的，没有注册的端点，这个呼叫只能以一种莫名其妙的方式失败。

#### 麦克风

页面会在打开时检查一次有没有音频输入设备（这个检查**不需要权限**，也不会打开设备）。

**没有麦克风也能打电话。** 页面会自己接管本地媒体，在没有麦克风时喂一条静音音轨 ——
因为 WebRTC 没有本地音轨就构不出 offer，通话会在发出任何信令之前就死掉。
代价是对方听不到你，页面会明确告诉你这一点。

各种麦克风问题的文案是**分开的**，因为它们要采取的行动不同：

| 提示 | 该怎么办 |
|---|---|
| 未找到麦克风 | 插一个，或者接受对方听不到你 |
| 麦克风权限被拒绝 | 在浏览器地址栏放行 |
| 麦克风被其他应用占用 | 关掉那个应用 |
| 只在 HTTPS 下授予权限 | 用 https 访问控制台 |

上面这些**都不会阻止拨号** —— 拨服务代码、查话费、听语音信箱都不需要麦克风。

#### 服务代码

像 `#225#` 这样的服务代码**可以直接拨**。页面会在拼 SIP URI 之前把 `#` 转义 ——
RFC 3261 不允许 `#` 出现在 URI 的用户部分，而 JsSIP 会直接拒绝整个 URI 而不是转义它。
不转义的话这类号码根本发不出去。

有些运营商支持语音播报余额，这类代码**没有文本回复**，回复是通过语音通道来的。
运营商返回的 USSD 文本会挂在通话记录上（见下）。

#### 通话中的控制

- **静音 / 取消静音**
- **拨号盘（DTMF）** —— 按 IVR 提示输入分机号时必须用这个
- **录音** —— 录完出现下载链接（本地生成，不经过网关）

#### 接听来电

有来电时会出现一个带「接听 / 拒接」的块。

**拒接用的是 603，不是简单挂断。** 这个区别有实际后果：简单挂断会让 Asterisk 把这次通话
记成「未接」，而你明明是主动拒接的。用 603 才会被记成「已拒绝」。

同时来第二路来电时会自动回 486（忙），不会打断第一路，也不会给对方留语音留言。

#### 如果一直注册不上

按可能性排序：

1. **证书是自签的** —— 浏览器会直接拒绝这个 WSS 连接，而且原因不会明说。
   见部署手册第 6 节。
2. **8089 端口不可达** —— 软电话连的是引擎自己的端口，**不经过反向代理**。
3. **改完证书没重启线路** —— 证书是挂载进容器的，必须重建容器才生效。
4. **页面不是 HTTPS** —— 浏览器不给麦克风，WSS 也会被判为混合内容。

「端点信息」折叠块里能看到实际要连的 WSS 地址，排查时先看那个。

### 8.2 蜂窝通话

**不依赖浏览器** —— 即使软电话完全没连，这一栏也能拨号。

状态的含义：

| 状态 | 含义 |
|---|---|
| 无蜂窝通话 | 空闲 |
| 拨出中… | 模块已发出 AT 指令，运营商还没确认 |
| 已接通 | 通话建立 |
| 已结束 | 结束 |
| **未确认** | 模块接受了指令，但运营商没有确认 |

**「未确认」是一个真实且重要的状态。** 这种情况既不能报成功也不能报失败 ——
所以它单独显示，并且下面会告诉你「最后一次报告的状态是什么」。
页面会持续轮询状态，直到模块给出确定答复。

「模块状态」那一行显示的是**模块自己的原话**（`dialing` / `ringing-out` / `active` /
`terminated` 等），上面那个徽章是页面对它的解释。

### 8.3 通话记录

两条通道写的是**同一个日志**，每条记录标了传输方式（Wi-Fi Calling / 蜂窝网络）。

记录里有：方向、号码、状态、时间、时长、传输方式。

**服务回复** —— 如果这次通话是服务代码且运营商返回了文本，会挂在记录上。
网关**不解析**这个文本，原样显示 —— 所以你看到什么就是运营商说了什么。

可以单条删除，也可以「清空记录」（需要点两次确认）。

### 8.4 语音留言

引擎在配置为接收留言的线路上会录音。列表里有对方号码、时间、时长、文件大小、是否听过。

- 点「播放」直接在页面里放，**并自动标记为已播放**。
- 未播放的条目有数量角标。

## 9. AT 终端

直接和模块对话。**排障时最缺的就是这个** —— 信号质量、注册状态、PDP 上下文、USSD 服务代码，
以及所有结构化面板没暴露的东西，在这里都能问出来。

### 9.1 它不会打断线路

这是最重要的一点。命令走 **ModemManager**，而不是网关自己独占串口 —— 所以
**线路运行中也能用**，而这恰恰是最需要它的时候。

代价是每条命令约一秒。手动敲命令的人不会察觉。

### 9.2 三档命令

页面按**「损坏要花多大代价才能撤销」**分档，不是按命令看起来吓不吓人：

| 档位 | 例子 | 行为 |
|---|---|---|
| **已阻止** | IMEI/NV 写入（`AT+EGMR`、`AT+QPRTPARA`）、原始 SIM APDU（`AT+CSIM`、`AT+CRSM`）、改波特率（`AT+IPR`）、固件下载模式 | 直接拒绝，**没有绕过开关** |
| **需要确认** | 射频开关（`AT+CFUN=`）、复位（`AT&F`）、PIN 输入（`AT+CPIN=`）、PDP 上下文写入、手动选网、发短信 | 确认框里写明后果后才执行 |
| **允许** | 查询（`?` 结尾）、`ATI`/`AT+CGMI`/`AT+CSQ` 这类裸信息命令、USSD | 直接执行 |

几条要知道的判定：

- **查询永远放行** —— 查询不可能改变状态。
- **「没有等号」不等于「只读」**：`ATD` 是拨号、`ATA` 是接听、`ATH` 是挂断，全是裸命令，
  其中一个还花钱。所以这类要确认。
- **被拒绝的命令根本不会到达模块**，也不会进输出区 —— 输出区记录的是「模块被问过什么」。
- **确认在服务端强制**。页面上的对话框只是方便，跳过它也没用。

### 9.3 怎么用

上面有**常用诊断**按钮（型号、IMEI、信号、注册状态、运营商、IP、PDP、射频状态），
和**服务代码**按钮（查余额、查话费）—— 后者是这一页存在的主要理由。

输入框里：

| 按键 | 作用 |
|---|---|
| 回车 | 执行 |
| ↑ / ↓ | 翻历史 |
| Ctrl+L | 清屏 |

**历史按线路分开保存**，刷新页面不丢。

### 9.4 USSD

服务代码（`#225#`、`*100#` 这类）**在只读模式下也能用** —— 查余额是无害的。

**回复内容就是运营商发来的原文**，网关不解析它。所以看到什么就是运营商说了什么。

### 9.5 只读模式

默认允许改状态的命令。如果这台机器只该被观察，在控制面环境里设：

```
MDD_AT_TERMINAL_ACTIONS=0
```

此时只有查询和 USSD 放行。

## 10. 余额与保号

这一页解决一个具体问题：**预付费卡长期不活动会被注销，而余额又需要偶尔查一下。**

### 10.1 余额

余额是**运营商给的原文**，不是算出来的数字。所以像 `£4.20`、`4.20 GBP`、`$12`
这种格式都会**原样显示**。

字段包括：余额、有效期、剩余短信、剩余流量、剩余通话、激活日期。

> **余额只在能读出数字时才参与判断。** 如果运营商返回的措辞读不出数字，页面会显示它，
> 但**不会**拿它去判断「余额不足」—— 显示一个读不懂的余额，好过瞎猜一个。

激活日期必须是 `YYYY-MM-DD` 格式。

### 10.2 查询规则

规则决定「怎么问运营商要余额」。常见方式是发一条特定短信到特定号码，
或者拨一个 USSD 服务代码。

**如果一条规则还没有生效值（`effective`），点查询会返回 409 并明确告诉你原因** ——
而不是静默地什么都不做。

### 10.3 保号计划

两个动作：

| 动作 | 做什么 |
|---|---|
| **发送短信** | 定时给某个号码发一条短信，制造活动记录 |
| **仅观察余额** | 只查余额，不主动发短信 |

参数：

| 参数 | 范围 | 说明 |
|---|---|---|
| 间隔天数 | **1–365**（默认 30） | 多久做一次 |
| 短信内容 | **≤160 字符** | 超出会被拒绝 |
| 目标号码 | — | 发到哪 |

#### 三个必须知道的约束

1. **「立即执行」会发一条真实计费短信。** 不是模拟。所以按钮需要二次确认。
2. **只在本地时间 10:00–22:00 之间执行。** 凌晨 3 点给运营商发短信既没用又容易招来风控。
3. **失败后 3600 秒（1 小时）重试。**

#### 排期是按「最后一次成功」算的，不是最后一次尝试

这一点很重要：**一条离线过的线路，不会因为失败就把计划整体往后推一个周期。**
计划锚定在最后一次**成功**执行的时间上。否则一条断线三天的线路，恢复后要再等一整个
周期才会被保号 —— 而它本来已经该被保号了。

执行结果会通过通知渠道发出来（如果配了 `keepalive_result` 事件）。

## 11. eSIM

管理 eUICC 上的 profile：读卡、下载、启停、改名。

### 11.1 两种读卡方式（重要区别）

| 方式 | 会不会打断线路 | 什么时候用 |
|---|---|---|
| **读卡（排他读）** | **会** | 需要最新状态时 |
| **读缓存** | 不会 | 日常查看 |

**「读卡」是排他操作，会打断正在运行的线路。** 因为它要独占读卡器去跟卡通信。
日常只是看看 profile 列表，用「读缓存」就够了。

### 11.2 lpac 是单线程的

底层工具 lpac 在所有读卡器之间**是单线程的**。所以：

- 不能同时对两张卡发起读操作。
- 一个下载任务进行中时，其他读卡操作要排队。
- 正在跑的线路占了读卡器时，读卡会失败或需要等待。

**不要同时开两个 eSIM 操作。** 页面会拦住一部分，但你自己心里要有数。

### 11.3 下载 profile（九步）

下载是一个**后台任务**，进度通过 WebSocket 实时推过来，可以离开页面再回来。

九个步骤是：

1. 读取默认 SM-DP+
2. 获取 eUICC 挑战值
3. 与 SM-DP+ 认证
4. 认证服务器
5. 认证客户端
6. 配置预览
7. 准备下载
8. 获取配置包
9. 安装到 eUICC

**第 6 步「配置预览」是给你确认的机会** —— 它会显示这个 profile 的运营商、名称等信息，
确认无误再继续。

**下载同一张 profile 是覆盖，不是追加。** 一个 ICCID 在 eUICC 上只存在一条记录 ——
所以重下不会出现两条重复的 profile。

### 11.4 切换 profile 会中断线路

启用/禁用 profile 会改变卡上哪个配置是活动的，**这会导致线路中断**。

所以页面会先弹确认框再执行。切换完成后线路需要重新建立隧道。

### 11.5 多 eUICC 清单

页面底部有一个**「eUICC 清单」**面板，列出网关认识的所有 eUICC —— 板载的、可插拔的、
一张双 SE 卡会算作两个安全元件。每个条目显示 EID、读卡器、IMEI、配置数（启用/总数）、
读取时间，以及**哪条线路在用它**。

**默认视图来自缓存，不碰任何卡。** 「读取所有卡」是一次明确的动作，因为它排他、串行
（lpac 单线程），而且会把读卡器从正在运行的线路上拿走 —— 所以要先确认。

三种状态，区别很重要：

| 显示 | 含义 |
|---|---|
| **在读卡器中** | 刚刚被某个读卡器报告 |
| **在读卡器中（读数已旧）** | 报告过，但那次读取已经超过 6 小时 |
| **未核实** | **只在缓存里** —— 没有任何读卡器报告它 |

**「未核实」既不说它在，也不说它不在。** 缓存以 EID 为键，卡片被取走时不会有任何东西
删除那条记录。想知道就点「读取所有卡」。

如果刷新后有条目显示「有 N 张缓存中的卡没有任何读卡器报告」，那就是这个信号 ——
它可能被拔了，也可能只是某个读卡器读失败了。

### 11.6 字段命名

profile 的字段来自 lpac，用的是驼峰命名（`profileNickname`、`profileName`、
`serviceProviderName`、`profileState`、`profileClass`）。
`profileState` 是 `enabled` / `disabled`（大小写不敏感）。

「不是 eUICC」（普通 USIM）和「没有卡」是两种不同的错误，页面会分开告诉你。

## 12. 网络出口

这一页管的是**流量从哪个国家出去**。对 VoWiFi 来说，出口决定了运营商看到你从哪里接入。

### 12.1 代理库

先在这里定义代理资源，四种类型：

| 类型 | 说明 |
|---|---|
| **订阅（subscription）** | 一个订阅 URL，里面包含多个节点 |
| **节点（node）** | 单条分享链接（Reality / XHTTP 等） |
| **SOCKS5** | 一个 SOCKS5 代理 |
| **直连（direct）** | 不走代理 |

**订阅和节点可以测速，SOCKS5 也可以。** 只有这三类能被单独拨测。

### 12.2 国家出口

每个国家一条，指向代理库里的某个条目。

页面上的状态：

| 显示 | 含义 |
|---|---|
| **就绪** | 出口可用 |
| **未就绪** | 出口起不来，会给出原因 |
| **直连** | 这个国家不走代理 |

### 12.3 UDP 校验：为什么必须做，而且失败了必须显示成失败

**每个非直连出口都必须通过 UDP 校验。** 原因是 IKEv2/ESP 的 NAT-T 需要 **UDP 500/4500**。

这意味着一件很重要的事：**一个能承载网页浏览的节点，完全可能承载不了 VoWiFi。**

所以：

- **校验失败就显示为失败**，绝不显示成「慢」。
- **失败时绝不显示任何延迟数字** —— 因为延迟数字会让人以为「只是慢一点，能用」。

如果一个节点在 TCP 上很快但在 UDP 上不通，它对你的 VoWiFi 就是没用的。
页面存在的意义就是**不掩盖这一点**。

### 12.4 节点锁定

可以把某个国家的出口**锁定**到代理库里的一个具体节点，两种模式：

| 模式 | 含义 |
|---|---|
| **锁定（lock）** | 就用这个节点，不自动切换 |
| **优先（prefer）** | 优先用这个节点，不可用时允许自动切换 |

页面会明确区分三种异常：

- **被手动锁定** —— 你锁了它，所以它不会自己换。
- **锁定于 X，实际运行在别处** —— 你锁的节点没被用上，需要看原因。
- **锁定的节点已不再由其订阅提供** —— 订阅更新后那个节点没了。
  这个和「出口报错」是**分开显示**的，因为处理方式不同。

### 12.5 状态新鲜度（重要）

出口状态是**宿主编排器定期发布的**，不是控制面实时算的。所以页面上有一个「发布于多久前」。

**如果这个时间超过 60 秒，说明编排器可能停了。** 这时页面会提示你去检查编排器 ——
因为编排器一停，出口状态就会**静默冻结**在最后一刻的样子，看起来一切正常，其实已经不更新了。

### 12.6 什么时候会请求迁移

网关**不会**随便换出口：

- 如果某个出口已经**稳定运行超过 10 分钟**，网关**不会**再请求迁移 ——
  这说明出口已经证明能承载 IMS，故障另有原因，换出口解决不了。
- 如果你**手动锁定**了，或者设成了**直连**，网关**无条件尊重**，不会自动迁移。

## 13. 通知

六个渠道：**Webhook、Telegram、PushPlus、飞书 / Lark、Bark、邮件**。

### 13.1 十个事件

| 事件 | 什么时候触发 |
|---|---|
| 收到短信 | 任何线路收到一条短信 |
| 来电 | 有来电 |
| 宿主告警 | 宿主机出问题（磁盘、Docker、USB） |
| 号码变更 | 运营商改了这条线路的号码 |
| 线路无法恢复 | 重试多次仍起不来 |
| 保号执行结果 | 保号计划跑了一次（成功或失败） |
| 余额不足 | 余额低于阈值 |
| 未接来电 | 有未接来电 |
| 收到语音留言 | 有人留言 |
| 软件更新 | 有新版本 |

其中「宿主告警」「号码变更」「线路无法恢复」是**网关级**的，不带 SIM 身份。

### 13.2 每个渠道独立配

**事件开关是按渠道分开的。** Webhook 和 Telegram 经常需要不同的事件子集，
所以不是全局一套开关。

**渠道关掉就是关掉。** 即使事件开关都打开，渠道是关的就什么都不会发。

**没有打开开关的事件永远不会被投递**，模板写得再对也一样。

### 13.3 消息模板

每个事件可以单独覆盖标题和正文。模板里可以用 `{{变量}}`：

```
event   instance   sim_name   iccid   msisdn   from   text   title   content
```

**变量名打错会被拒绝。** 页面会在你输入时就标出未知的变量（服务端只报第一个错误，
本地检查能一次告诉你全部）。

留空 = 用默认文案，不需要手写一遍。

### 13.4 各渠道的特别之处

| 渠道 | 注意 |
|---|---|
| **Webhook** | `generic` 是通用 JSON；`custom` 可以自定义载荷和消息体模式。额外请求头用 JSON 对象写（放认证信息）。 |
| **Telegram** | 需要 Bot Token 和 Chat ID。可以选走代理（直连 / 代理库 / 国家出口 / 手动 URL）。**同一个 bot 还能反过来收命令**，见 13.7。 |
| **PushPlus** | 需要 token；可选群组编码做群发；内容类型 html/txt/markdown/json。 |
| **飞书 / Lark** | URL **必须是**自定义机器人地址（`https://open.feishu.cn/open-apis/bot/v2/hook/…` 或 larksuite 的），别的会被拒。可以配签名密钥。 |
| **Bark** | iOS 上最省事的一种：不用建 bot、不用拉群，一个设备 Key 就行。「服务器」留空用公共的 `api.day.app`，自建就填自己的地址。打扰级别里 `critical` 会绕过静音开关（需要在 App 里单独授权）。 |
| **邮件** | 标准库 SMTP，不引入新依赖。传输方式三种：`starttls`（587）、`ssl`（465）、`none`（25）—— **端口跟随传输方式**，除非你显式指定。收件人可以填多个，用逗号或分号分隔。 |

> **Bark 和 PushPlus、飞书一样，HTTP 200 也可能是失败** —— 它们在应用层报错时照样回 200。
> 所以投递日志会校验响应体里的错误码：看到红色「失败」但状态码是 200，就是这个情况。

### 13.5 测试投递

每个渠道都有「发送测试」，可以选择用哪个事件的模板渲染。

**测试和真实投递走的是同一条代码路径** —— 所以测试通过就说明真的能发出去。

**渠道没启用时测试按钮是灰的**，并且会告诉你为什么。这是故意的：拿关闭的渠道去测试，
只能得到「一个永远不会发生的事成功了」这种没有意义的结论。

### 13.6 投递记录

日志**只记元数据**：

```
id  时间  渠道  事件  线路  状态  尝试次数  HTTP 状态码  错误
```

**通知正文、号码、凭据一律不落盘。** 这个日志的用途是诊断，不是留档。

「投递中」和「历史」是分开的 —— 正在飞的和已经完成的是两件事。

> **HTTP 200 也可能是失败。** PushPlus 和飞书在应用层报错时**照样返回 200**。
> 所以日志会校验响应体里的错误码 —— 看到红色「失败」但状态码是 200，就是这个情况。

### 13.7 Telegram 双向 Bot

同一个 bot 除了收推送，**还能反过来给你执行命令**。它默认是关的，需要在设置里配白名单。

| 命令 | 需要确认 | 说明 |
|---|---|---|
| `/help` `/status` `/lines` `/esim <线路>` | — | 只读 |
| `/sms <线路> <号码> <内容>` | ✅ | **会真的发短信并计费** |
| `/balance <线路>` | ✅ | 查询会向运营商发短信，可能计费 |
| `/switch <线路> <ICCID>` | ✅ | 会断线，需要重建隧道 |
| `/wfc <线路> on\|off` | ✅ | 会改射频状态 |
| `/confirm <令牌>` `/cancel` | — | 确认 / 取消 |

**四条要理解的规则：**

1. **白名单为空 = bot 根本不启动。** 不是「谁都行」—— 是「谁都不行，直到你告诉它谁能用」。
   `allowed_chat_ids` 是 bot token 和「任何找到这个 bot 的人」之间唯一的东西。
2. **不在白名单里的会话得到的是沉默**，不是「未授权」。回复等于确认 bot 活着。
3. **确认令牌只能用一次、120 秒过期、绑定到发起它的会话。** 泄到群里的令牌别人用不了。
   另外同一会话里 30 秒内不能连发第二条改状态的命令。
4. **`/help` 之外的任何命令名都不会被执行**，只会回一份帮助。

> **怎么拿到自己的 chat id**：给 bot 发一条消息，然后浏览器打开
> `https://api.telegram.org/bot<TOKEN>/getUpdates`，找 `result[].message.chat.id`。

## 14. 设置

六个标签页。

### 14.1 硬件

**USB 模块登记表。** 编排器拿 `(VID, PID)` 查这张表，查不到就不认这块设备。

每行：名称、VID、PID、AT 接口号。

- VID/PID 是**四位十六进制，不带 `0x`**。写错和「设备没插」表现完全一样，
  所以表单会拦下不是四位十六进制的输入。
- **AT 接口号**指的是 USB 接口索引，`2` 就是「接口 2 上的那个 tty」。
- 大疆一代蜂窝模块是 `2ca3:4006`，AT 口在接口 2 —— 页面上有一键加入。

还有「自动探测 USB」开关（每次 reconcile 时重新扫描）和「模块后端」：

| 后端 | 说明 |
|---|---|
| `auto` | ModemManager 运行，功能齐全 |
| `serial` | 不跑 ModemManager，只保留 Wi-Fi Calling |

`serial` 是给那些 ModemManager 报不稳定的主机（虚拟机、容器）用的。
**代价是蜂窝数据、飞行模式、蜂窝短信都会停掉，只有 VoWiFi 继续工作。**

### 14.2 新设备默认值

**只在这个设备第一次出现时生效。** 改它不会影响已经配好的设备。

飞行模式的默认是「关」—— 网关只在需要救回卡死的线路时才强制开。

### 14.3 VoWiFi 与通话

IMS 会话相关的参数：User-Agent、`user=phone`、PANI、接入类型、振铃超时、
语音留言开关与时长。

**`user=phone`** —— 某些 IMS 核心要求请求 URI 上带 `;user=phone` 才会路由语音 INVITE。
如果电话拨不出去但短信正常，这里值得一试。

### 14.4 主机

- **时区** —— 「剩余天数」是个日历问题，所以时区会影响它。
- **引擎重试** —— 次数和间隔。
- **维护** —— 通知历史保留天数、支持包里的日志行数。
- **安全** —— 仅 HTTPS、审计日志、**可信代理**。
- **引擎调试** —— 打开后日志更详细（也更吵）。

> **这里没有的几件事**：更新策略、TLS 证书路径、Docker 镜像/构建缓存的清理、备份还原。
> 它们是设置文档的一部分，但**这个控制台没有渲染对应界面** —— 请到网关自带界面
> `https://<网关主机>:8443` 里操作，或用主机命令。详见部署手册第 8 节。

> **可信代理**：反代必须在列表里，否则控制面不认它发来的 `X-Forwarded-For`，
> 所有请求会被算到反代这一个 IP 上。后果是登录限流会误伤 —— 一个人输错密码，
> 所有人一起被锁。

### 14.5 eSIM

只编辑 lpac 的三项配置。**profile 的增删改和下载进度在 eSIM 页**，不在这里。

### 14.6 管理员

改密码等。

### 14.7 保存行为

设置页**只提交你改过的顶层区块**，其余部分原样保留。

但如果某个区块你编辑了，它会**整块**发出去 —— 所以本页不渲染的键也不会被悄悄丢掉。

校验在客户端就做了（因为一次被拒绝的请求只值一次往返，而错误信息远不如
「是哪一行哪个字段错了」有用）。被拒绝会返回明确的字段级原因。

## 15. 危险操作速查

这些操作**会真的产生影响**，动手前先确认：

| 操作 | 位置 | 后果 |
|---|---|---|
| **「立即执行」保号** | 余额与保号 | **发出真实计费短信**，不是模拟 |
| **「读卡」（排他读）** | eSIM | **打断正在运行的线路** |
| **切换 profile** | eSIM | 线路中断，需要重新建隧道 |
| **清空记录 / 删除录音** | 通话 | 不可恢复（录音文件一起删） |
| **删除通话记录** | 通话 | 不可恢复 |
| **清理旧版与回滚镜像** | 网关自带界面 → 系统设置 → 维护 | **放弃一键回滚能力** |
| **卸载 --purge** | 主机命令 | 删除运行数据，无法恢复 |
| **改线路的 PIN** | 线路 | 留空不会清 PIN；填错会锁卡 |
| **在 AT 终端发 `AT+CFUN=0`** | AT 终端 | 关射频，线路立刻掉线（有确认框） |
| **在 AT 终端发 `AT+CPIN=`** | AT 终端 | PIN 连续输错 3 次会永久锁卡（有确认框） |
| **Telegram `/sms`** | Telegram bot | **发出真实计费短信**（有确认框） |
| **Telegram `/switch`** | Telegram bot | 线路中断（有确认框） |
| **「读取所有卡」** | eSIM → eUICC 清单 | 读卡器会被逐个占用，期间线路中断 |

另外：**关掉 4G 不会停 ModemManager**，也**不会**隐式进飞行模式 —— 三个能力是独立的。

## 16. 常见任务

| 我想… | 去哪 |
|---|---|
| 看现在整体正不正常 | 概览（三个计数 + 主机告警） |
| 加一张新卡 | 插卡 → 概览确认 → 线路里配置并启用 |
| 让线路走某个国家 | 网络出口：先建代理条目，再配国家出口，然后**测 UDP** |
| 知道某条线路为什么起不来 | 线路 → 引擎日志 |
| 查话费 | 余额与保号（先配查询规则） |
| 防止卡被注销 | 余额与保号 → 保号计划 |
| 换 eSIM 的运营商 | eSIM → 下载 profile → 切换（会断线） |
| 用浏览器打电话 | 通话 → 连接软电话（需要证书，见部署手册第 6 节） |
| 只用模块打电话 | 通话 → 蜂窝通话（不需要软电话注册） |
| 有人打电话来要知道 | 通知 → 打开「来电」事件 |
| 出问题要收到提醒 | 通知 → 至少配一个渠道，打开「宿主告警」「线路无法恢复」 |
| 加一块新模块 | 设置 → 硬件 → 加一行 VID/PID/AT 接口 |
| 模块认不出来 | 主机上跑 `mdd-modem-driver-repair.py`（见安装说明） |
| 问模块一个问题（信号、注册、PDP） | AT 终端 → 常用诊断按钮 |
| 查余额（用服务代码） | AT 终端 → 服务代码按钮 |
| 在手机上查状态 / 发短信 | Telegram bot（需要先配白名单） |
| 看我有几张 eUICC、哪条线路用哪张 | eSIM → eUICC 清单 |
| 忘了密码 | 主机上 `sudo ./install.sh reset-admin` |

## 17. 出问题先看哪里

| 现象 | 先看 |
|---|---|
| 登录后立刻跳回登录页 | Cookie 没发出去。部署手册 5.0 |
| 左下角一直「重连中」 | `/ws` 没通。部署手册「界面一直显示重连中」 |
| 线路起不来 / STOPPED | 1. 模块登记了吗 2. 线路 → 引擎日志 3. `sudo ./install.sh diagnose` |
| 拨号按钮是灰的 | 软电话没注册。看「端点信息」里的 WSS 地址 |
| 软电话一直未注册 | 证书是自签的 / 8089 不通 / 没重启线路 |
| 对方听不到我 | 麦克风问题，页面上会写是哪种 |
| 蜂窝通话「未确认」 | 正常状态，等轮询给出确定答复 |
| 收不到短信了 | 模块存储满了（设置里的短信存储策略） |
| 出口状态不动了 | 「发布于」超过 60 秒 → 编排器停了 |
| UDP 校验不过 | 这个节点承载不了 IKEv2/ESP NAT-T，换一个 |
| 通知没发出去 | 1. 渠道启用了吗 2. 事件开关打开了吗 3. 看投递记录 |
| 测试发得出但真实事件收不到 | 事件开关。测试用的是你选的事件模板 |
| 一个人输错密码所有人被锁 | 可信代理没配。设置 → 主机 → 安全 |
| AT 终端说「只接受 AT 命令」 | 命令必须以 `AT` 开头。查状态用 `AT+CSQ`、`AT+CREG?` |
| AT 终端一直「模块没有响应」 | ModemManager 不可用，或这条线路还没有 ICCID/IMSI |
| AT 终端把命令拒了 | 那是一条会永久损坏模块或 SIM 的命令，没有绕过开关。看拒绝理由 |
| Telegram 发命令没反应 | 1. 白名单里有没有你的 id 2. 日志里找 `ignoring message from unauthorised chat` |
| Telegram 回「没有这个命令」 | 群聊里要 `@bot`；`/help` 看列表 |
| Telegram 回「请等 N 秒」 | 同一会话 30 秒内不能连发第二条改状态的命令 |
| Telegram 确认令牌说无效 | 令牌只能用一次、120 秒过期、且只能在发起它的会话里用 |
| eUICC 清单是空的 | 点「读取所有卡」。还空就看面板里有没有列出读卡器 |
| eUICC 清单里显示「未核实」 | 正常 —— 那张卡只在缓存里，没有读卡器报告它。点「读取所有卡」核实 |
| Bark 测试失败但状态码是 200 | 应用层报错。看投递记录里的错误文本 |
| 邮件发不出去 | 1. 端口和传输方式是否匹配（587+starttls / 465+ssl）2. 有些服务商用独立的应用密码而不是登录密码 |

**排障的通用顺序**：概览看全局 → 线路看引擎日志 → **AT 终端问模块本人** → 通知看投递记录。
这四处能定位绝大多数问题。
