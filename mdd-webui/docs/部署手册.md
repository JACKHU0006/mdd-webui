# 部署手册

本文面向**第一次把整套系统装起来的人**。读完应该能从一个空主机走到「浏览器里能登录、
能看到线路、能收发短信」。

> 版本基准：网关本体 `v1.10.0`，控制台为本次重写的实现。
> 文中所有 `gateway.example.com` / `mdd-origin.example.net` / `/srv/mdd-webui` 都是占位符，
> 换成你自己的值。

---

## 0. 先搞清楚这套东西由两部分组成

这是**最容易搞错的一点**，也是后面所有排查的起点。

| | 网关本体 | 控制台（本仓库） |
|---|---|---|
| 是什么 | Python 控制面 + 每张 SIM 一个 Docker 引擎 | 纯静态前端（HTML/JS/CSS） |
| 跑在哪 | **必须有 USB 口和 root 的主机**（树莓派、NUC、软路由、PVE 虚拟机） | 任何静态托管；生产环境还需要一个同源前置 |
| 干什么 | 跑 IKEv2/IPsec 隧道、Asterisk IMS、lpac、ModemManager | 只画界面、调控制面的 HTTP API |
| 能不能放云上 | **不能**（没有 USB、没有 TUN、没有 root） | 能，而且推荐 |

控制台是**纯静态**的，本身不含任何后端逻辑。它需要的是一个**同源的反向代理**把
`/api/*` 和 `/ws` 转发到网关，其余路径回落到静态文件。第 5 节讲这件事。

---

## 1. 选一种部署形态

| 形态 | 前端在哪 | 网关在哪 | 软电话 | 适用 |
|---|---|---|---|---|
| **A. Cloudflare Worker 同源前置**（推荐） | Worker 静态资源绑定 | 家里/机房 + Cloudflare Tunnel | 可用（需证书，见第 6 节） | 日常使用，一个域名搞定，不需要公网 IP |
| **B. 自有域名 + 反向代理** | nginx / Caddy 的静态目录 | 同机或内网 | 可用（需证书，见第 6 节） | 已有公网 IP 或已有反代 |
| **C. 纯演示（Pages）** | Cloudflare Pages | 不存在，用 Mock | 不可用 | 展示界面，不接硬件 |

**形态 A 和 B 的区别只有一个：谁来当那个同源前置。** 其余步骤完全一样。

## 2. 前置条件

### 2.1 硬件

- **主机**：ARM64 或 amd64，Debian / Ubuntu / Armbian。推荐 4 核 4 GB 内存起步。
- **系统盘**：根文件系统至少 **2 GiB** 可用，建议 8 GB 以上，并留约 3 GiB 给升级期间
  两代镜像共存。
  - 实测占用：Engine 镜像 607 MB；两代镜像共享基础层后合计约 676 MB；源码与虚拟环境
    约 102 MB；运行数据数月后约 75 MB；Docker 控制面模式另需 355 MB。
  - 虚拟机扩了虚拟硬盘之后**必须扩根分区和文件系统**，以 `df -h /` 为准，不能看控制台
    显示的虚拟硬盘容量。
- **USB 蜂窝模块**：见 2.4。
- **SIM 卡**：能读出 ICCID 的实体卡；或者一张可写的 eUICC（用于 eSIM）。
- **读卡器**：如果 SIM 不直接插在模块上，需要一个 PC/SC 读卡器。

### 2.2 主机与系统

- systemd 可用（安装器会注册 systemd 单元）。
- Docker：如果系统已有可连接的 Docker，安装器**只复用**它 —— 不升级版本、不改 daemon
  配置、不动其他项目的容器/镜像/卷。
- 内核 TUN、`pcscd`。
- **蜂窝与 TUN/PCSC 引擎需要系统级 Docker daemon，不支持 rootless 模式。**

### 2.3 网络与域名

- 一个你控制的域名（形态 A/B 都需要，因为 Cookie 是 `SameSite=Strict`，见 5.0）。
- **不需要公网 IP、不需要开任何入站端口** —— 形态 A 走 Tunnel。
- IKEv2/ESP 需要的 **UDP 500/4500 不需要对公网开放**：VoWiFi 是网关**主动出站**到运营商
  ePDG 的，不依赖任何入站端口。

### 2.4 USB 蜂窝模块必须登记，否则等于没插

编排器拿 `(idVendor, idProduct)` 去 `hardware.modem_profiles` 查表
（`host/mdd_orchestrator.py::usb_modems()`），**查不到就当这块设备不存在** ——
插着也没用，而且表现上和「设备没插」完全一样。

大疆一代蜂窝模块（DJI Cellular Dongle，Quectel EG25-G）是 `2ca3:4006`，AT 口在 USB
接口 2，需要这样一条：

```json
{ "name": "DJI Cellular Dongle", "vid": "2ca3", "pid": "4006", "at_interface": 2 }
```

设置页的「硬件」页有**一键加入这条配置**的按钮（`添加 DJI Cellular Dongle (2ca3:4006)`），
不用手写 JSON。

### 2.5 三体电子 SCR Prime 读卡器（如果用到）

SCR Prime（`04d9:c001`）提供标准 CCID 接口，但**尚未进入 libccid 1.6.2 的设备表**，
所以默认认不出来。连接该型号时执行：

```bash
sudo ./install.sh patchprime
```

安装器会从校验过的固定版本源码构建驱动并加入设备匹配，完成后支持热插拔。

## 3. 第一步：部署网关本体

### 3.1 获取源码

```bash
git clone https://github.com/MddIdd/mdd-sim-gateway.git
cd mdd-sim-gateway
```

也可以从 GitHub Release 下载正式源码包。**正式包和开发 checkout 的区别**：

- 正式包内含 CI 生成的镜像校验清单，安装器默认下载本机架构的**预构建镜像**（快）。
- 开发 checkout 没有该清单，会**从源码构建**（慢，需要额外数 GiB 磁盘）。
- 正式包也可以显式 `MDD_BUILD_IMAGES=1` 走源码构建（审核用）。

Release 资产下载或身份校验失败时**安装会停止**，不会悄悄退回一次耗时且占空间的编译。

### 3.2 安装

```bash
sudo ./install.sh install                 # 原生控制面 + Docker 引擎（默认）
sudo ./install.sh install --mode docker   # 控制面也跑在 Docker 里
```

首次安装会创建管理员密码前的初始化状态；**在受信的局域网或 VPN 中**打开
`https://<主机地址>:8443` 完成初始化（见第 7 节）。

> **首次设置完成前，任何能访问 8443 端口的客户端都可以申领初始管理员。**
> 所以不要在公网上裸奔这一步 —— 要么先在内网做完初始化，要么用 Tunnel/防火墙挡住。

### 3.3 环境变量

可以写在脚本同目录的 `.env` 里，也可以直接传给命令。

| 变量 | 默认 | 说明 |
|---|---|---|
| `MDD_MODE` | `local` | `local`（原生控制面）或 `docker`（控制面也在容器里） |
| `MDD_PORT` | `8443` | 控制台对外端口 |
| `MDD_DATA_DIR` | `<repo>/data` | 运行数据目录 |
| `MDD_BIND` | `0.0.0.0` | 控制面监听地址 |
| `MDD_ADVERTISE_ADDR` | 自动探测 | 供 SIP/WebRTC 媒体使用的本机 LAN IP |
| `MDD_CELLULAR_SMS_STORAGE` | `delete` | 模块短信存储策略，见下 |
| `MDD_BUILD_IMAGES` | — | 置 `1` 强制源码构建镜像 |
| `MDD_REUSE_WEBUI` | — | 置 `1` 复用源码包里已构建好的 `webui/dist` |
| `MDD_ENGINE_BASE_IMAGE` | — | 离线迁移用的可信本机引擎镜像 |
| `PJPROJECT_REPOSITORY` / `ASTERISK_REPOSITORY` | 项目 mirror | 全量构建时的 Git 仓库覆盖 |

**短信存储策略**（`MDD_CELLULAR_SMS_STORAGE`，也可在配置文件
`settings.cellular_sms_storage` 里覆盖，配置文件优先）：

- `delete`（默认）：短信入库后从模块删除，避免模块存储写满后**再也收不到短信**。
- `when_full`：保留在模块里，只在快满时删除最早的已入库短信。需要 ModemManager 以
  `--debug` 运行（靠 `AT+CPMS?` 读容量）；否则按 `MDD_CELLULAR_SMS_STORAGE_LIMIT`
  （默认 20 条）估算。
- `keep`：始终保留在模块中。**从旧版本升级上来的安装，首次启动会自动写成 `keep`**，
  需要时手动改成 `delete`。

`MDD_DATA_DIR` 在首次安装后会写入 `/etc/mdd-sim-gateway/data-dir`，之后执行
`status` / `reload` / `uninstall` **不必再填**，以免自定义数据目录被误判成新安装。

### 3.4 常用子命令

```bash
sudo ./install.sh install [--mode local|docker]   # 全新安装
sudo ./install.sh reload  [--mode …] [--no-cache] [--engines|--no-engines]
sudo ./install.sh start | stop | restart
sudo ./install.sh status
sudo ./install.sh diagnose
sudo ./install.sh logs
sudo ./install.sh reset-admin                     # 管理员密码忘了
sudo ./install.sh enable-autostart | disable-autostart
sudo ./install.sh build-lpac [--lpac-src PATH]    # 本机编译 eSIM LPA
sudo ./install.sh patchprime                      # SCR Prime 读卡器驱动
sudo ./install.sh uninstall [--purge]
```

`./install.sh status` 和 `logs` 不需要 root。模式会被记住，`reload` / `status` /
`logs` / `uninstall` 都不用再传 `--mode`；显式 `--mode` 或 `MDD_MODE` 永远优先。

### 3.5 验证网关装好了

```bash
sudo ./install.sh status
curl -sk --noproxy '*' https://127.0.0.1:8443/api/auth/status
```

第二条应该返回 JSON（`{"configured":false,...}` 或 `{"configured":true,...}`）。
能返回就说明控制面活着。然后 `docker ps` 应该能看到带 MDD 归属标签的容器。

### 3.6 补齐功能（可选，但推荐）

网关本体装好之后，还有一批**上游没有、但这份工程补上了**的功能：

| 功能 | 作用 |
|---|---|
| 大疆模块驱动修复 | 让 `2ca3:4006` 被认出来 —— 不写 NV、不改 USB 身份 |
| AT / USSD 终端 | 直接问模块：信号、注册状态、PDP、服务代码。**线路运行中也能用** |
| Bark / 邮件通知 | 通知渠道从四个变六个 |
| Telegram 双向 Bot | 在手机上执行命令（带白名单与一次性确认） |
| 多 eUICC 清单 | 看有几张 eUICC、哪条线路用哪张 |

它们是**独立的新增文件 + 少量登记行**，不改上游既有逻辑，所以以后合并上游更新不会冲突。

完整步骤见 **[补齐功能安装说明](../../mdd-addons/安装说明.md)**。最省事的做法是先把那五组
测试跑一遍（不需要硬件、不需要网关），确认没问题再往 fork 里并。

> 如果你只是想先把网关跑起来、以后再说，这一步可以跳过 —— 跳过不影响任何上游功能。

## 5. 第三步：把控制台接上去

### 5.0 先说清楚为什么不能「前端放 Pages，直接调网关 API」

控制面的会话 Cookie 是这么设的（`control/app/auth.py`）：

```python
SESSION_COOKIE = "mdd_session"
response.set_cookie(..., httponly=True, secure=True, samesite="strict", path="/")
```

`SameSite=Strict` 的含义是：**浏览器不会把这个 Cookie 附在任何跨站请求上。**

如果前端在 `mdd-console.pages.dev`、网关在 `gateway.example.com`，那么从前者请求后者
就是跨站 —— 即使两个域名都是你的、都是 HTTPS。结果是一个非常迷惑的现象：

1. 登录请求成功，响应里带 `Set-Cookie`
2. 浏览器**确实存下了**这个 Cookie
3. 但下一个请求（`GET /api/devices`）浏览器不会带上它
4. 控制面返回 `401 authentication required`，界面跳回登录页

你会以为是密码错了或后端坏了，其实只是 Cookie 根本没发出去。

**不要试图去改控制面**把 `SameSite` 改成 `None`。那会削弱一个刻意的安全设计（Strict 是
防 CSRF 的第一道防线），而且 `SameSite=None` 还要求 `Secure` 且必须显式配 CORS
`Access-Control-Allow-Credentials`，等于为了部署方便把攻击面扩大。

**正解是让浏览器只看到一个源。**

### 5.1 形态 A：Cloudflare Worker 同源前置（推荐）

Worker 绑在 `gateway.example.com`，`/api/*` 和 `/ws` 反代到 Tunnel，其余走静态资源。
浏览器只看到 `gateway.example.com`，Strict Cookie 是同站的，CSRF 原样工作，
**控制面一行都不用改**。

#### A-1. 在网关主机上建 Tunnel

```bash
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg \
  | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null

echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] \
https://pkg.cloudflare.com/cloudflared any main" \
  | sudo tee /etc/apt/sources.list.d/cloudflared.list

sudo apt-get update && sudo apt-get install -y cloudflared

cloudflared tunnel login
cloudflared tunnel create mdd-origin
```

`~/.cloudflared/config.yml`：

```yaml
tunnel: mdd-origin
credentials-file: /root/.cloudflared/<TUNNEL-UUID>.json

ingress:
  # 控制面监听 8443，自签证书。noTLSVerify 是必须的：Tunnel 出口到源站这一段
  # 已经在 Cloudflare 的加密通道内，源站证书只是自签，验证它没有意义。
  - hostname: mdd-origin.example.net
    service: https://127.0.0.1:8443
    originRequest:
      noTLSVerify: true
      # WebSocket 是控制面推送状态的主通道，必须允许。
      httpHostHeader: 127.0.0.1:8443

  - service: http_status:404
```

```bash
sudo cloudflared service install
sudo systemctl enable --now cloudflared
```

> Tunnel 只承载 HTTP/HTTPS/TCP。**UDP 500/4500 不能通过 Tunnel 暴露，也不需要** ——
> VoWiFi 是主动出站。Tunnel 只用来访问管理界面。

#### A-2. 配置并部署 Worker

```bash
npm install -D wrangler
npx wrangler login
```

编辑 `wrangler.jsonc`，把两处占位符改掉：

```jsonc
"routes": [
  { "pattern": "gateway.example.com", "custom_domain": true }
],
"vars": { "ORIGIN": "" }   // 保持为空，用 secret 注入
```

`ORIGIN` 保持为空是**故意的**：代码在 `ORIGIN` 未设置时会返回 500 并明确说明原因，
而不是静默转发到错误的地址。

```bash
npx wrangler secret put ORIGIN
# 输入：https://mdd-origin.example.net

npm run build
npx wrangler deploy
```

访问 `https://gateway.example.com` 即可。

#### A-3. 验证 Cookie 确实发出去了

排查时最有用的一条命令 —— 直接看响应头：

```bash
curl -sI --noproxy '*' https://gateway.example.com/api/auth/status
```

应该看到 `set-cookie: mdd_session=...; HttpOnly; Secure; SameSite=Strict`。

如果浏览器仍然登录不上：开发者工具 → Application → Cookies，确认
`gateway.example.com` 下**有** `mdd_session`；再看 Network 里 `/api/devices` 的请求头
是否带了 `Cookie`。

### 5.2 形态 B：自有域名 + 反向代理

原理与形态 A 完全相同，只是把 Tunnel 换成你自己的反代。**前提是网关主机有公网 IP，
或者你能从反代所在机器访问到它。**

#### nginx

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name gateway.example.com;

    ssl_certificate     /etc/letsencrypt/live/gateway.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/gateway.example.com/privkey.pem;

    root /srv/mdd-webui/dist;
    index index.html;

    # 控制面 API
    location /api/ {
        proxy_pass https://127.0.0.1:8443;
        proxy_ssl_verify off;              # 控制面是自签证书
        proxy_set_header Host 127.0.0.1:8443;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto https;
    }

    # 实时通道：必须单独配 WebSocket 升级头，否则界面会一直显示「重连中」
    location /ws {
        proxy_pass https://127.0.0.1:8443;
        proxy_ssl_verify off;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host 127.0.0.1:8443;
        proxy_read_timeout 3600s;          # 别让空闲超时把长连接切掉
    }

    # 静态资源 + SPA 回落
    location / {
        try_files $uri /index.html;
    }
}
```

#### Caddy（更省事，WebSocket 自动处理）

```
gateway.example.com {
    handle /api/* {
        reverse_proxy https://127.0.0.1:8443 {
            transport http {
                tls_insecure_skip_verify
            }
            header_up Host 127.0.0.1:8443
        }
    }
    handle /ws {
        reverse_proxy https://127.0.0.1:8443 {
            transport http {
                tls_insecure_skip_verify
            }
            header_up Host 127.0.0.1:8443
        }
    }
    handle {
        root * /srv/mdd-webui/dist
        try_files {path} /index.html
        file_server
    }
}
```

> **`Host` 头必须改写成 `127.0.0.1:8443`。** 控制面用它来决定一些自引用地址；
> 原样透传 `gateway.example.com` 会让它以为自己跑在公网域名上。

> **如果反代不在网关主机上**，控制面默认只信 `X-Forwarded-For` 来自可信代理的请求。
> 在「设置 → 主机 → 安全 → 可信代理」里把反代的 IP 或 CIDR 加进去，否则登录限流会把
> 所有请求算到反代这一个 IP 上，几个人一起输错密码就会互相锁住。

### 5.3 形态 C：纯演示（Cloudflare Pages）

不接后端，用于展示界面。

```bash
VITE_DEMO_MODE=1 npm run build
npx wrangler pages deploy dist --project-name mdd-console-demo
```

部署后界面顶部会出现「演示模式」提示条。

> `VITE_DEMO_MODE=1` **只是加提示条**，不会自动接上 Mock 后端。要让演示版真的能点，
> 需要把 `mock/server.mjs` 改造成 Pages Functions 或单独部署到一个 Node 环境。
> 静态 Pages 只能展示只读骨架。

### 5.4 关于 Vercel

Vercel 只适合形态 C。两个硬限制：

1. Vercel 的 Serverless Function **不支持 WebSocket**。实时状态推送会失效，界面会一直
   显示「重连中」，只能靠 30 秒轮询兜底。
2. Vercel 无法承载 UDP，也无法承载网关本体（没有 USB、没有 TUN、没有 root）。

**实时状态推送是 Cloudflare Workers 才能给的**，这也是推荐 CF 而不是 Vercel 的原因。

## 6. 让浏览器软电话能用（最容易漏的一步）

**如果你不用浏览器打电话，可以跳过本节。** 蜂窝通话（由实体模块拨出）走的是 8443 上的
控制面，不受本节影响。

### 6.1 软电话连的是哪里

浏览器软电话**不经过反代**。它直连引擎容器发布到主机的 **8089 端口**：

```
wss://<你访问控制台的那个域名>:8089/ws
```

这个地址是控制面 `GET /api/instances/{iid}/softphone` 算出来的 —— `host` 取自请求的
`Host` 头，`ws_port` 取自引擎的 `ports.webrtc`（默认 8089）。所以：

- **8089 必须从浏览器可达**（防火墙/安全组放行）。
- **控制台必须走 HTTPS**，否则浏览器不给麦克风权限，且 WSS 会被判为混合内容。

### 6.2 证书：自签的浏览器一定拒绝

引擎的 WSS 监听需要一张证书，来源顺序是：

1. `settings.tls.cert_path` + `settings.tls.key_path`（显式配置，**推荐**）
2. 回落到控制面的自签证书 `$MDD_DATA/certs/self-signed.{crt,key}`

**自签证书会让浏览器直接拒绝这个 WSS 连接**，表现是软电话一直「未注册」，而且原因
不会直接告诉你。控制面在缺证书时会在日志里写一条 warning：

```
no TLS cert available for engine <iid> WSS/8089 — browser softphone will not connect until a cert exists
```

所以要用软电话，**必须换成真证书**。把证书放到数据目录下（例如
`$MDD_DATA/certs/fullchain.pem` 和 `privkey.pem`），然后写入设置：

```bash
# 1. 登录并保存 Cookie
curl -sS --noproxy '*' -c /tmp/mdd.jar -X POST https://gateway.example.com/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"username":"admin","password":"<你的密码>"}' -o /dev/null

# 2. 取 CSRF token（所有写操作都要带）
CSRF=$(curl -sS --noproxy '*' -b /tmp/mdd.jar https://gateway.example.com/api/auth/status \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["csrf"])')

# 3. 写入证书路径（顶层浅合并，只提交 tls 这一个键是安全的）
curl -sS --noproxy '*' -b /tmp/mdd.jar -X PUT https://gateway.example.com/api/settings \
  -H 'content-type: application/json' \
  -H "x-mdd-csrf-token: $CSRF" \
  -d '{"tls":{"cert_path":"<数据目录绝对路径>/certs/fullchain.pem","key_path":"<数据目录绝对路径>/certs/privkey.pem"}}'
```

路径规则：数据目录**外**的绝对路径按原样使用；以 `/data/` 开头的路径会被翻译成宿主机的
数据目录路径（为 Docker 控制面模式准备）。

> 也可以直接在**网关自带界面**（`https://<网关主机>:8443`）里填这两项 ——
> 本次重写的控制台没有渲染 TLS 分区，所以那里是唯一的图形入口。

> **改完证书必须重启线路。** 证书是作为 bind mount 挂进引擎容器的，只有重建容器才会
> 生效。在线路页把该线路停一下再启动，或 `sudo ./install.sh restart`。

> **一个已知的坑**：早期版本在 Docker 控制面模式下会把证书路径存成容器内的 `/data/...`，
> 而引擎是兄弟容器，绑定挂载需要宿主路径。结果是 WebUI 显示证书配好了，Asterisk 却
> 悄悄回落到旧的自签证书，浏览器拒绝连接。控制面已经做了路径翻译，但如果你从很旧的版本
> 升上来，配完证书请**实际打开通话页确认能注册**，不要只看设置里填了什么。

### 6.3 如果不想暴露 8089

可以只把 8089 限制在局域网/VPN 内，代价是软电话只能在局域网用；蜂窝通话和其余全部功能
不受影响。也可以让控制台只在局域网访问，不接 Cloudflare —— 那样形态 A/B 的复杂度归零，
但也就没有外网访问了。

## 7. 首次初始化

1. 在受信网络里打开 `https://gateway.example.com`（或 `https://<主机IP>:8443`）。
2. 界面会进入**创建管理员**流程 —— 密码要求 **10–256 字符**。
3. 创建完成后进入控制台。

登录相关的行为，部署后值得知道：

- 会话有效期 **12 小时**；勾选「记住我」是 **30 天**。
- 连续 **5 次**密码错误，该来源 IP 会被锁 **60 秒**。
- 密码忘了：`sudo ./install.sh reset-admin`。

接下来该做的是**登记 USB 模块**（设置 → 硬件，或一键加入 DJI 配置），否则线路永远起不来。
然后插卡 → 概览页应该出现一张待配置的卡 → 在线路页完成配置。

具体操作见 [操作手册](操作手册.md)。

## 8. 升级

> ### 先说清楚：现在有两个界面
>
> 网关本体**自带一个 WebUI**，监听在 `https://<网关主机>:8443`。本仓库的控制台是
> **另写的一个前端**，通过 Worker/反代挂在你自己的域名上。两者读同一份设置文档，
> **并存不冲突**。
>
> 它们的覆盖面不同，这点很重要 —— 下面这些功能**只在网关自带界面里有**，
> 本次重写的控制台没有渲染（它们是 API 契约的一部分，但界面没做）：
>
> - **更新策略**（自动更新 / 提示更新、全部版本 / 主版本）
> - **TLS 证书路径**（`settings.tls`）
> - **维护清理**（Docker 镜像与构建缓存的可回收空间、清理按钮）
> - **备份与还原**
>
> 所以：日常用本控制台；**升级、配证书、清磁盘这几件事，直接开网关自带界面**
> `https://<网关主机>:8443`，或者用下面 8.2 的主机命令。

### 8.1 从界面升级（推荐）

在**网关自带界面**（`https://<网关主机>:8443`）的系统设置里选「自动更新」或
「提示更新」，并分别选「全部版本」或「主版本」。

- 新安装默认**自动更新主版本**。
- 每个通道仍须匹配目标版本并到达自己的 `not_before` 时间 —— **单纯发布 Release
  不会触发安装**。
- 提示模式下左下角版本号出现红点，由管理员确认「立即升级」。

升级过程：控制面把请求写入编排器目录 → 主机上的 `mdd-sim-gateway-orchestrator` 以独立的
临时 systemd 单元（`mdd-sim-gateway-update`）运行 `host/mdd_update.py` → 下载对应
`vX.Y.Z` 资产、校验 SHA-256 和版本、比较引擎指纹 → 导入新镜像 → 保存旧引擎的
`:previous` 回滚标签 → 只重建旧镜像上的线路 → 重新扫描在位 SIM 使线路自愈。

`data/`、`.env`、`.git` 和虚拟环境**都会保留**。

升级日志：

```bash
journalctl -u mdd-sim-gateway-update
# 以及数据目录下：
#   update/reload.log
#   update/engine-image.log
```

### 8.2 手动升级

备份并用受信任来源更新源码后：

```bash
sudo ./install.sh reload --engines
```

该方式保留数据并从固定源码重建依赖与引擎。正式一键升级优先使用 CI 分发镜像。

### 8.3 联网方式

「设置 → 备份与更新」默认「自动」：先直连 GitHub，连接失败/超时/被限流时再按代理库顺序
尝试可用条目；检查成功的线路会继续用于更新下载。也可以选「仅直连」或指定一个代理库条目。

> 订阅、具体节点和导入的 outbound 需要**已分配给一个已启用且就绪的国家出口**才能用于
> 更新下载。代理凭据只保存一份，只通过权限为 `0600` 的配置文件传递，不写入 systemd
> 命令行或升级状态。

控制面不依赖浏览器登录，**每 6 小时**检查一次 Release。

### 8.4 前端单独升级

前端是纯静态的，升级就是重新构建 + 重新部署：

```bash
npm ci && npm run build
npx wrangler deploy        # 形态 A
# 或把 dist/ 同步到反代的静态目录（形态 B）
```

前后端**版本不必一致**：控制台只依赖控制面的 HTTP 契约。但如果控制面升级引入了新的
接口或字段，旧前端不会知道它们的存在（不会报错，只是不显示）。

## 9. 卸载

```bash
sudo ./install.sh uninstall            # 保留数据
sudo ./install.sh uninstall --purge    # 同时删除运行数据与虚拟环境，无法恢复
```

卸载**只移除确认属于 MDD 的容器**；Docker 本身及其他项目不受影响。前端侧删掉 Worker
或静态目录即可。

- [ ] 8089 端口从浏览器可达

- [ ] 通话页点「连接软电话」后显示「已注册」

## 11. 排障

### 登录成功但立刻跳回登录页

**九成是 Cookie 没发出去**（跨站）。按 5.0 检查：开发者工具 → Application → Cookies 看
`mdd_session` 是否存在，Network 看 `/api/devices` 有没有带 `Cookie` 头。
如果前端和网关不同源，回到第 5 节改成同源。

### 界面一直显示「重连中」

`/ws` 没通。按顺序查：

1. 反代/Tunnel 是否转发 `/ws`（nginx 必须配 `Upgrade` + `Connection` 头）。
2. 静态资源绑定的 `run_worker_first` 是否包含 `/ws`（`wrangler.jsonc` 里已配好）。
3. 反代有没有把空闲连接超时设得太短（nginx 用 `proxy_read_timeout`）。

界面有 30 秒轮询兜底，所以「重连中」不等于数据是旧的，只是不实时。

### 线路起不来 / 显示 STOPPED

1. **USB 模块登记了吗？**（2.4 节）这是最常见的原因，且表现与「没插设备」一样。
2. `sudo ./install.sh logs` 看引擎日志。
3. `sudo ./install.sh diagnose`。
4. 概览页的引擎日志面板里看 IKEv2 协商在哪一步失败。

### 软电话一直「未注册」

按可能性排序：

1. **证书是自签的** → 浏览器拒绝 WSS。见第 6 节。
2. **8089 不可达** → 防火墙/安全组。
3. **改完证书没重启线路** → 证书是 bind mount，要重建容器。
4. **页面不是 HTTPS** → 浏览器不给麦克风，且 WSS 是混合内容。
5. 引擎日志里 `docker logs <engine容器>` 看 Asterisk 有没有绑定 8089。

### 收不到短信 / 收到一阵后收不到了

看 `MDD_CELLULAR_SMS_STORAGE`（3.3 节）。默认 `delete` 是**故意的** —— 模块存储写满之后
就再也收不到短信了。如果你手动改成了 `keep`，记得偶尔清理模块存储。

### 反代后面登录限流把所有人锁住

控制面按来源 IP 限流。反代必须正确设置 `X-Forwarded-For`，并且反代的 IP 要在
「设置 → 主机 → 安全 → 可信代理」里登记，否则所有请求都算到反代这一个 IP 上。

### 装了补齐功能之后启动失败

先看日志里的第一行错误：

| 报错 | 原因 |
|---|---|
| `ImportError: cannot import name 'notify_channels'` | 文件没拷到 `control/app/` 下 |
| `AttributeError: module 'notify_push' has no attribute 'send_bark'` | 补丁里写成了 `notify_push.send_bark`，实际在 `notify_channels` 里 |
| 通知页看不到新渠道 | 前端没更新 —— 那是**另一个仓库**（`mdd-webui`） |
| 保存设置返回 400 | 第 3.3 步的校验没加，或渠道配置不完整（启用的渠道必须有 key/主机/收件人） |

完整排查见 [补齐功能安装说明](../../mdd-addons/安装说明.md) 第 8 节。

### 磁盘不够

```bash
sudo ./install.sh status     # 会显示可回收空间
```

**网关自带界面**的「系统设置 → 维护」可以分别查看 Docker 镜像和构建缓存的实际可回收
空间（本次重写的控制台没有这个面板）：

- **清理构建缓存**：只执行 Docker 的保守 dangling-only 清理。
- **清理旧版与回滚镜像**：**显式放弃一键回滚**，只删除未被任何容器使用的 MDD 历史镜像，
  保留当前 Engine/Control 与可信 Engine 基础镜像。

两项操作都不会删除容器、卷或其他项目的镜像。
